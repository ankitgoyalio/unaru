# Domain docs

This repository uses a single-context layout.

## Read before exploring

Read root `GLOSSARY.md` and the decisions in `docs/adr/` relevant to the work.
If these files do not exist, proceed silently. The `domain-modeling` skill creates them when terms or decisions are resolved.

## Use glossary terms

Use the terms defined in `GLOSSARY.md` in issue titles, proposals, hypotheses, and test names.
If a term is missing, check whether the project already uses another term. Record unresolved terms for `domain-modeling`.

## Report conflicts with decisions

If a proposal contradicts an existing ADR, identify that ADR and explain why the decision needs reconsideration.
