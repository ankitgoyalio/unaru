# Commands and input

On iPadOS 26 and later, use the app menu bar as a discoverable command surface. Group document/content actions, put destination changes and sidebar visibility in View, and disable unavailable commands instead of hiding the menu structure. The standard Settings item opens the app’s page in iPadOS Settings; place internal preferences in a separate item in that group. Provide shortcuts for frequent operations using standard meanings; keyboard access to all core actions does not require a unique shortcut for every item.

Keep touch operation complete when accessories are absent. Route commands to the focused window and selected content. Use keyboard navigation for text, sidebars, and collections; standard buttons and switches use Full Keyboard Access rather than a custom focus-navigation system. Preserve system-reserved shortcuts.

The iPadOS 26 pointer is an arrow with updated hover behavior. Let system controls adapt to it; validate custom hover effects on each supported OS instead of rebuilding the older circular-pointer magnetism. Pointer hover can improve feedback but cannot be the only way to discover or perform an action. Make band or range selection available when collections benefit from multi-selection.

Sources: [The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar), [Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards), [Pointing devices](https://developer.apple.com/design/human-interface-guidelines/pointing-devices), [Elevate the design of your iPad app](https://developer.apple.com/videos/play/wwdc2025/208).
