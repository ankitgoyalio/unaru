# Controls, presentation, and feedback

Choose list grouping for the content structure; inset grouping is useful for grouped settings, not a universal style.

Place frequent actions in visible controls or toolbars. Context menus, swipe actions, and custom gestures need a discoverable control or menu path to the same core operation. 

Use a sheet for a bounded task with an explicit completion or cancellation path. Size it for its content and larger text; use full-screen presentation for immersive work that benefits from it. An alert interrupts for a consequential decision or actionable failure. Reversible editing usually benefits from Undo rather than repeated confirmation.

Show progress near the affected content. Placeholders fit loading content whose structure is known; loading itself does not require a skeleton. Keep unaffected work usable, and preserve input on failure with a recovery action. Haptics reinforce meaningful feedback alongside visual cues.

Sources: [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets), [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts), [Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators), [Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures), [Undo and redo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo).
