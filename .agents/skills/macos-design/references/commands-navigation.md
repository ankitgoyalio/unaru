# Commands, navigation, and input

## Menu bar is the durable command surface

Preserve standard app, editing, window, and help commands that apply to the app. Use File for document operations and View for display/navigation changes. Put every toolbar action in the menu bar too, so hiding or customizing a toolbar leaves it reachable. Keep labels and grouping stable; disable unavailable commands and validate against the focused document or selection.

Give frequent commands familiar keyboard shortcuts; less frequent commands remain keyboard reachable through menus and focus without inventing a shortcut for each. Use the Settings scene or native settings command for app preferences. Context menus contain useful item-specific actions, rather than appearing on every button.

## Content and input

Use a collapsible sidebar for libraries or hierarchical destinations, outline disclosure for trees, and native document tabs where multiple documents benefit from tabbing. A sidebar-adaptable TabView maps to a sidebar on Mac; choose the information architecture before prescribing a control.

Toolbars expose frequent content actions; customization is useful for rich workflows. Supply meaningful icon labels and tooltips, and retain essential commands through overflow or menus as windows shrink. Search should communicate its scope, with system search behavior and suggestions where useful.

Support keyboard focus and arrow-key navigation in collections. Selection should follow standard range and noncontiguous modifier behavior. Use native contextual clicks and trackpad scrolling, plus drag/drop where content transfers or reordering are meaningful. Custom cursors communicate a content operation; standard buttons retain native pointer behavior. Provide Undo for reversible editing with action-specific menu titles.
